# Security

Harpie manages sensitive local files. Use only disposable identities when reproducing a bug. Never attach a private key, passphrase, access token, or an unredacted SSH configuration to a report.

If you find a vulnerability, contact the repository owner privately through an existing trusted channel. If GitHub's private vulnerability reporting is enabled, use **Security → Report a vulnerability**. Avoid public reports containing exploit details until a fix is available.

Include the Harpie version, Windows version, expected behavior, and reproduction steps using temporary keys. Treat release checksums as integrity checks; they do not constitute executable code signing.
